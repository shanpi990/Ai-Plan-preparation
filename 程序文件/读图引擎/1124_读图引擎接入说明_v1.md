# 读图引擎 v1 接入说明

整套文件夹可以搬到其他 Windows x64 电脑。运行库内含 Python 3.11、PDF 读取组件和 OCR 模型。审查端用子进程读图，用自己的 Python 3.12 导入参数模块。

## 命令行

在引擎文件夹内打开 PowerShell。将下例中的输入、输出路径换成实际路径。

```powershell
.\读图引擎.bat selftest
.\读图引擎.bat ocr --pdf "D:\图纸\设计总说明.pdf" --pages 1-7 --out "D:\读图结果\总说明" --parallel 6 --threshold 165
.\读图引擎.bat crop --pdf "D:\图纸\设计总说明.pdf" --page 3 --bbox "120,240,560,310" --pad 12 --out "D:\读图结果\原文.png"
```

读整份 PDF 可省略 `--pages`。页码从 1 开始，也可指定 `1,3-5`。每份 PDF 分配一个输出目录，多页分别写到 `page_1.json`、`page_2.json` 等文件。有原生文字层时，`text` 先包含原生文字，再接 OCR 结果。`--force` 只返回 OCR 文字。`lines` 总是 OCR 行，坐标以 PDF 显示方向的点为单位，顺序为左、上、右、下。

中断后重用相同的 `--out`。引擎按 PDF 内容摘要、阈值和页码复用灰度图、已完成瓦片和识别行组。同一目录同时只接收一个读图任务。收到本次 `page` 事件后即可读取对应页，`file` 是绝对路径。截取原图时用该页的 `lines[i]["bbox"]`，默认向四周各留 12 点，结果为 144 dpi PNG。

## 批量读图

重复传入 `--pdf` 和 `--out`。每个输入按顺序对应一个独立输出目录。整批共用一个进程池，`--parallel` 指整批的工作进程数。

```powershell
.\读图引擎.bat ocr --pdf "D:\图纸\图一.pdf" --out "D:\读图结果\图一" --pdf "D:\图纸\图二.pdf" --out "D:\读图结果\图二" --parallel 6
```

批量调用时，`--pages`、`--threshold` 和 `--force` 作用于每份 PDF。省略 `--pages` 时各自读取全部页。每个文件的页码从 1 起算。批量 `progress` 和 `page` 事件带有 `document`，值为输入文件的序号，从 1 开始。页面可按任意顺序完成，用 `document` 和 `page` 定位，`tile` 和 `tileCount` 统计整批进度。最终 `done.documents` 按输入顺序列出各文件的 `document`、`pdf`、`out` 和 `pages`。后续单独读其中一份、或整批重跑，都可复用同一个输出目录下的缓存。

## 审查端调用

桌面程序直接启动随包解释器。命令参数逐项传递，可包含空格或中文。`CREATE_NO_WINDOW` 用于在后台运行。以下自检示例等待真实识别完成，返回值可用于设置页状态。

```python
import json
from pathlib import Path
import subprocess

def engine_selftest(folder):
    folder = Path(folder).resolve()
    cmd = [str(folder / "运行库/python.exe"), "-B", "-X", "utf8",
           str(folder / "读图引擎.py"), "selftest"]
    result = subprocess.run(cmd, capture_output=True, encoding="utf-8",
                            creationflags=subprocess.CREATE_NO_WINDOW)
    event = json.loads(result.stdout.splitlines()[-1])
    if result.returncode:
        raise RuntimeError(event["message"])
    return event
```

OCR 长任务使用 `subprocess.Popen`，后台逐行读取标准输出，每行都是一个 UTF-8 JSON 对象。按 `progress` 更新进度，按 `page` 加载本页，按 `done` 结束。`tile` 表示已完成检测的瓦片数，达到 `tileCount` 后文字识别可能仍在运行。失败返回非零退出码和 `error.message`。标准错误可单独接日志文件，避免与事件流混合。

## 在 Python 3.12 中提取参数

```python
import sys

sys.path.insert(0, str(engine_folder))  # 包含“图纸参数提取.py”的目录
from 图纸参数提取 import FIELDS_BY_TYPE, GENERIC_FIELDS
from 图纸参数提取 import batches, build_prompt, validate_items, numeric_conflicts

fields = FIELDS_BY_TYPE["设计总说明"]
lines = page_data["lines"]
candidates = []
for a, b in batches(lines):
    prompt = build_prompt(doc_name, "设计总说明", lines, a, b, fields)
    items = call_model(prompt)["items"]  # 使用调用方已有的模型连接
    accepted, rejected = validate_items(items, lines, a, b, fields,
                                        doc_id, doc_name, page_data["page"])
    candidates.extend(accepted)
conflicts = numeric_conflicts(candidates, confirmed_keys=[])
```

批次是左闭右开区间，行号从 0 开始，沿用整页索引。候选含原文摘录、来源页和坐标证据。由调用方去重、分配持久化 ID，并记录拒收项。`confirmed_keys` 接受已人工确认且有值的 `(分区, 字段名)` 对，冲突按同一组键返回。已有项目需要复现编制端动态字段时，用 `sorted(set(FIELDS_BY_TYPE["设计总说明"]) | 项目参数名集合)`。勘察报告等选择对应资料类型的字段表，其他方案需要概况级参数时使用 `GENERIC_FIELDS`。
